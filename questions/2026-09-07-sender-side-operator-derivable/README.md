# 设计理由：比较了什么、排除了什么、为什么

## 候选怎么来的

不是从 exloop 探索来的，来源见 `origin/provenance.md`：一次具体的接入需求
（把自研模拟器 mapsim 接进 newlife）撞上 `writing-a-world.md` 里那段加粗警告。

检索三个来源，结论 `unknown`：

| 来源 | 结果 |
|---|---|
| 项目自己（第十八个里程碑、`derive.py`、`foreign.py`） | **接收端**已解决（store type 的 add/set，行为探针 3/3）；**发送端**仍是 `foreign.py` 自己写明的「an assertion, not a fact read off the third party」 |
| FMI / co-simulation 文献 | 标准做法是接口描述由模型作者随实现交付，未见「靠跑一跑问出来」的工作 |
| 动态不变量检测（Daikon 一族） | 手法上是上一层（跑起来反推性质），未见覆盖 delta/level 这一实例 |

按 `newlife-goal` 的检索三分类，这是第二种（已知但只是上一层）→ 候选**磨快**而非作废，
问题改成「已有的行为探针手法能不能覆盖 process 返回值语义这个实例」。

## 排除了什么

- **不碰接收端**：第十八个里程碑已解决，重做等于重新发现。
- **不把探针接进 gate**：先有结论再决定要不要建设施（skill：工具只在卡住科学时才现在建）。
- **不拿 mapsim 当被试品**：它是动机来源，但还没接进来，用它等于同时引入一个新 wrapper 的
  不确定性。改用三个已接入且源码未改的现成样本。

## 探法比较

| 探法 | 为什么没选 / 选了 |
|---|---|
| 零时长 `update(state, 0)` | **起草时的第一直觉，动手前就被证伪**：求解器类 process 未必接受退化输入，且它假定 `update` 无副作用 |
| 状态置零 | 对乘性动力学无效——`Grow` 在 `mass=0` 时两种语义都返回 0，分辨不出 |
| **两点外推回 interval=0**（选中） | 不需要 process 接受零时长，只需能跑两个不同的短步；判别式直接对应语义定义（趋 0 = 增量，趋当前状态 = 绝对值） |

配套两条纪律，都来自登记：**每次探测用全新实例**（F5，防探测污染），
**裕度不足判 `indeterminate`**（第一版没有这一支，在一个全 0 的端口上把「什么都没测到」
静默输出成了确定判定——一个永远不会红的分支）。

## 事后看，S5 的设计是错的

S5 写成「把手写算符取反，探针判定必须与之不符」。它被 S4 逻辑蕴含，永远不会红。

**根因不是笔误，是结构性的**：F6 要求探针不读声明，所以声明的任何改动都影响不到探针
的输出。**真正的负控必须改变被探对象的行为**——S2 的 `LevelGrow` 正是这么做的，
但起草时没意识到负控也得走这条路。

处置照登记的规矩：判据不改，S5 照字面实现并通过，骨架自带的 S3「每条判据都能红」
因此为假，verdict 判 H0。让判定体系自己抓住它，而不是在散文里声明。

## 影响面

本里程碑**只在 `questions/` 下新增**，未改动 `packages/` 下任何库代码
（`git diff --name-only` 机械确认），因此不可能把别的世界的判定变成 `unevaluable`。
