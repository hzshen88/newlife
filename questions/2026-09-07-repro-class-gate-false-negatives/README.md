# 设计理由：比较了什么、排除了什么、为什么

## 候选怎么来的

上一个里程碑（`2026-09-07-sender-side-operator-derivable`）收尾时写的文档，自己在末尾
留下了这个问题：三级可复现性声明背后那三条机械判据「whether such a gate can actually
catch the mutation it is meant to catch … is itself a question worth registering rather
than assuming」。本里程碑就是去回答它。

检索三个来源，结论 `unknown`：判据本身是 2026-09-07 新写的、没有使用记录；git 边缘情况
（shallow clone 里 `git rev-list --merges` 假阴性、submodule 与 `depth=1` 冲突）是已知的，
**但没人测过这套特定判据在它们面前的表现**；artifact evaluation 的成熟清单是给人评审用的，
不是机械 gate。属于检索三分类的第二种（已知但只是上一层）→ 候选磨快而非作废。

## 关键设计：把「可复现」操作化

不写成形容词，写成可执行的检验：**按注册记下的信息（remote URL + commit + 内容摘要 +
数据校验和）在干净的地方重建并重跑，输出不同或重建失败 = 破坏可复现性。**

这条定义让每个变异都能**先自证**「我确实破坏了东西」，而不是靠散文声称。
本项目栽过两次的形状正是它的反面：拿一个测不出问题的变异去判「判据抓住了」。

## 排除了什么

- **不实现 gate**。先回答「这三条够不够」；答案出来前建 gate，是为没测量过的需求建设施。
- **不判「私有 remote」**。可达的 remote 未必公开，而这一点**没有机械测试能判**——
  答案已知的东西不该进清单。
- **不碰 `archived` 级**。DOI / 归档解析涉及外部服务。
- **不拿 mapsim 做被试品**。构造变异需要一个可随意破坏的仓库，用真项目会把破坏和
  真实状态混在一起。

## pilot 改掉的两处，以及为什么必须改

| 缺陷 | 为什么致命 |
|---|---|
| 重建函数直接拿 bare 仓库路径 clone，绕过 remote 配置 | 「删掉 remote」这个变异根本没生效——实验台把一个真实的失败建模没了。真实场景里注册能记下的只有 remote 给的 URL |
| 变异清单混进 `source_edited` / `data_edited` | 它们破坏的是「注册与实际不符」，不是「能不能重建」。**把「破坏」的定义扩过去，就成了用判据自己定义破坏、再看判据抓不抓得住的恒真圈——上一个里程碑的 S5 正是这么塌的。** 两者降级为 S3 的合成演示 |

第二条的教训直接冻成了 **F6**：破坏的判定不得引用三条判据中的任何一条。

## 影响面

本里程碑只在 `questions/` 下新增，未改动 `packages/` 下任何库代码，因此不可能让别的
世界的判定变成 `unevaluable`。收尾后单独一次提交更新了 `docs/writing-a-world.md`，
把这次发现的假阴性写进去——**判定先录先提交，修复另起一次提交**。
