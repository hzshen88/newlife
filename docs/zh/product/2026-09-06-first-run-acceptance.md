# 下一位真实新用户的验收单

**2026-09-06。这不是一个里程碑**：没有预注册，`results/` 里没有产物。本文是一张验收单，
等下一位第一次接触 newlife 的人来填。它来自 2026-09-06 一次外部评审的建议，评审在隔离目录里
走完了 init / pilot / freeze / check / audit，核实了六处缺陷（已修：S1 恒真、恢复提示走不通、
PyPI 落地页过期、`start` 缺 exloop 时仍承诺探索、pilot 输出伪装成判定、规则二判别句有歧义），
并指出**现有 68 条测试全绿时这些问题仍然在**——缺的是用户任务层面的验收。

## 为什么要人来填

门、扫描、自检、单元测试验的都是「机器该拒的它拒不拒」。**它们验不了「一个没读过任何文档的人
从一句话出发，能不能得到有用的反馈、离开、回来、接着做」**——那是产品的承诺，而承诺只能在
真人身上兑现或落空。作者自己不算：作者知道每条命令为什么存在。

## 五个任务

让第一次接触的人，在自己的机器上、用自己惯用的 AI 工具，各做一次：

1. **提出一个模糊的问题**，从"陪我探索 X"开始，看能不能走到一个更清楚的问题。
   走不到也算完成——"带走一个更清楚的问题"是第一次使用的合法结局。
2. **跑通一个示例**：从探索交接到判定，至少到 `newlife pilot` 出数。
3. **中断后继续**：关掉工具，隔一段时间回来，让 AI 说清"我们在哪一步"。
4. **理解一次不支持假设的结果**：让 H0 或 INVALID 发生一次，看用户能否说清它意味着什么、不意味着什么。
5. **从错误状态恢复**：故意 `git add -A` 提交 prereg.md，看 AI 能否带用户走到新文件夹。

## 记什么

| 指标 | 怎么量 | 及格线（第一轮先记，不设线） |
|---|---|---|
| 第一次得到有用反馈的耗时 | 从第一句话到用户自认"有用"的那条回复 | — |
| 是否需要作者临场解释 | 作者插话次数；每次记下插话的原因 | 0 是目标，先记实际 |
| AI 重复询问已知信息的次数 | 会话里同一件事被问第二遍的次数 | — |
| 用户能否说清当前阶段与下一步 | 任务 3 结束时，用户不看屏幕复述一遍 | 阶段与下一步都对 |
| 用户能否说清结果的证据边界 | 任务 4 结束时，用户复述"证明了什么、没证明什么" | 两句话分开说 |

**每条都记原话，不记评分。** 评分会把"哪里卡住"抹成一个数；原话才能指回某一条规则或某一行文本。

## 怎么处理结果

- 一条任务失败，先问它撞到的是**门、skill 文本、命令输出、还是 AI 的理解**，四者修法不同。
- 修完的每一条，回到本文把"及格线"那一格填上实测值，作为下一位的基线。
- 作者临场解释过的每一句话，都是文档或 skill 里缺的一句；逐条补进去，不留在口头。

## 还没做

- 没有人来填过。这张单子本身也是未验证的：任务是否恰当、指标是否可量，要等第一位真人。
- `newlife status` 是为任务 3 准备的机械读数（2026-09-06 落地），它读得对不对也要在任务 3 里验。
