# 第二十个里程碑：复现类别的可声明性

- **判定**：**H0**（`S5_l2_covers_every_bundle` 为假；其余五个单元全过）
- **产物**：`questions/2026-09-06-reproduction-class-declarability/results/summary.json`
- **预注册**：同仓，冻结 `876ed29`；**goal** 在 exloop-archive，冻结 `1b0a113`
- **形态**：**newlife 同仓形态的第一个里程碑**——预注册与产物同仓

## 1. 问题

`verdict.py` 只有一条复现安全绳：S0 逐字节重跑，且 `final = verdict if s0 else "INVALID"`。
对确定性世界这条又强又便宜；对本质不确定的世界（GPU 归约、并发、远端服务）它做不到，
于是那一整类世界**产不出任何 verdict**——不是结论弱，是拿不到。

问：三类复现声明（`deterministic` / `seeded` / `stochastic`）能否覆盖 `results/` 下已有的
bundle，且类别**由代码算出**而非由人说。

文献属「已知，但只是上一层」：`bitwise` 与 `statistical` 复现的二分在 HPC、地球系统建模、
天体物理都是成熟概念（天体物理 HPC 甚至已把统计层面复现当作成功标准），**但那是描述性
术语**，用来事后说明复现到什么程度；把它做成可判定的分类、并强制「声明哪一类就必须有
对应形状的判据」，未检索到先例。

|---|---|---|

**21 份参与分类，12 份 `unclassified`。**

## 3. H0 要拆开看：不是划分不够，是定位不到源码

**12 份的原因全部是 `no_runner_found`**，`rng_without_traceable_seed` 与
`mixed_seeded_and_stochastic` 各零份。也就是说：**三类划分在能定位到源码的 9 份上全部命中，
没有一份落进「特征表不够用」。** H0 来自「从 bundle 目录名猜 runner 文件名」这个辅助启发式
的能力，不是来自被研究的那个划分。

这一点能被一眼看出，靠的是预注册约束 6——`unclassified` 的原因取自固定值域、由代码算出，
散文不参与判定。**若原因是散文写的，这里就会变成事后给自己找台阶。**（第十八个里程碑的教训。）

## 4. L1 与 L2 的差：对手方论证的定量形式

goal 的 `@counterparty` 押 H0，理由是「复现类别是作者的**意图**，不是产物的**属性**」。
测量结果：

| | `deterministic` | `seeded` | `unclassified` |
|---|---|---|---|
| **L1**（只看产物） | 17 | 4 | **0** |
| **L2**（＋runner 源码） | 5 | 4 | **12** |

**L1 的「覆盖率 100%」是假的覆盖**——它不是分得清，是没有能力发现问题。两个具体证据：
`second-world` 在 L1 判 `deterministic`、L2 判 `seeded`（源码有 RNG 痕迹而产物没有）；
`nineteenth` 在 L1 判 `seeded`、L2 变 `unclassified`。**对手方在 L1 这一层是对的。**

**零份 `stochastic`**，与预注册 §0 记下的先验一致（`verdict_rot` 当日 7 份逐字节复现）。

## 6. 如实记录

- **21 份不是 22 份。** `v0.2` 没有 `summary.json`，被机械跳过（非人工挑选，约束 4 未违反）。
  但 §0 写「22 份」、H1 写「全部 bundle」，而**「bundle」从未被定义成「有 summary.json 的目录」**
  ——这是预注册措辞的一处不精确。不改变 H0（12 份已足够），记录在案。
- **`subprocess` 刻意不作为外部不确定源。** newlife 自己的复现设施就靠它重跑 runner，AST 层
  分不出「重跑自己」与「调一个不确定的外部程序」；纳入它会让所有世界判 `stochastic`——
  **一个到处都触发的特征什么都判不了**。代价是漏掉真调外部程序的 runner，已写进注册边界。
- **预注册有一处措辞在冻结前被实现纠正**：原写「pilot 指向合成样本目录」，实际用 `NEWLIFE_PILOT`。
  改成如实描述，并补上它为何不是「可选择性关闭判据」的口子——**该条件是单向的**，只由
  `newlife pilot` 设置，正式 run 从不设置，因此只能让 pilot 少算、永远不能让判定少算。
- **一个机制冲突，本轮未解决**：skill 要求收尾判定写进 goal 文档的「收尾判定」小节，
  而 goal 的 `@frozen` 锚对**整个文件**算哈希——填了 §7，哈希必然失效，「目标未被事后修改」
  的证明随之丢失。项目里没有先例（第十九个的 §6 至今为空）。**本轮的处置**：goal 文档保持
  冻结原样不动，收尾判定落在本文档，两者物理分开（这本就是 skill 的铁律）。
  **真正的修法应是让 `@frozen` 只覆盖被保护的章节**，而不是整个文件——留给后续。
