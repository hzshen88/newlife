# 第十九个里程碑 —— 产率是输入还是结果

- **goal**：`exloop` `goals/2026-09-04-newlife-yield-as-input-or-outcome.md`（冻结 `454ddb1`）
- **预注册**：`preregistrations/2026-09-04-newlife-yield-as-input-or-outcome.md`（冻结 `0e04160`）
- **判定**：**H1** —— `results/nineteenth/summary.json`
- **goal 收尾判定**：`achieved`

---

## 1. 这是产品形态的第一次端到端

两件事一起测：**科学**（网络层买到什么）+ **产品**（一个只用现成积木的新问题值多少行）。

**问题是积木自己长出来的**：`MonodKinetics` 与 `DynamicFBA` 的输入签名**逐字相同**，
在同一端口可互换；而 dFBA 内部用的**正是 Monod 摄取律**
（源码注释：「Set uptake bounds using Michaelis-Menten kinetics」）。

> **两个积木共用同一条摄取律，差别只在「摄取之后」。**

## 2. 结果

摄取律的对齐**不是手填**——Monod 的 `km`/`vmax` 在运行时从 dFBA 自己的
`kinetic_params` 读出（Z2 机械核对）。扫描 `EX_o2_e`：

| O₂ 下界 | dFBA 产率 | 乙酸 | Monod 产率 |
|---|---|---|---|
| −1 | 0.0552 | **1.216** | 0.99993 |
| −2 | 0.0834 | 0.175 | 0.99993 |
| −4 / −8 / −20 | 0.0863 | 0.000 | 0.99993 |

氧受限 → 分泌乙酸、产率降；氧充足 → 乙酸归零、产率到平台。**教科书式的溢流代谢**，
由第三方积木经我们的契约跑出来。

> **唯象模型把产率当输入（恒等于声明的 `yield`），机制模型把产率当结果。**

**判据的重心是负控 Z5**：把 Monod 的 `yield` 钉到 dFBA 某一点的产率，
它在其余点**仍然不动**——**对齐一个点 ≠ 表示这个自由度**。

## 3. 结论的边界（预注册 §5 事前声明，如实兑现）

**只证「固定形式的 Monod（单反应、常数产率）覆盖不了这个依赖」，
不证「任何唯象模型都覆盖不了」。** 给 Monod 加一条 `glucose→acetate` 反应就能
表示乙酸，但那是**换一个模型**，不是同一个模型的参数化。本轮明确不加。

## 4. 途中撞出一处真实的非确定性

**`PYTHONHASHSEED` 变了，Monod 的表观产率末位就变**（…365 ↔ …363）——
第三方代码路径上有 `set` 迭代，浮点求和顺序随之变。

与第十七个是同一形状（「逐字节复现买到的是同一个求解器的同一个选择」）。
照同样办法处置：**钉住种子并记进产物**，种子不对就重启自己并打印出来。

**补 `flush` 之前那行提示被 `execve` 吞掉了**——重启发生了但没人看得见，
**那就成静默了**。判据本身对这个抖动不敏感（容差 1e-3），但产物要逐字节稳定
就必须钉住它。实测：种子 0 / 3 / 7 下产物逐字节相同。

## 6. 判定缺陷的处置（2026-09-04 补记，外部红队触发）

**Z5 是一条恒真的负控，判定力为零。** 冻结判据原文是「`yield` 设成 dFBA 某点的
产率后**重扫**，Monod 产率仍逐点恒定（与氧无关）」，实现是：

```python
monod_pinned = [_run(MONOD, "foreign-monod", pinned) for _ in O2_SWEEP]
```

`O2_SWEEP` 被迭代，但**循环变量丢掉了**——五次跑的是同一份配置。
`scripts/probe_nineteenth_z5.py` 实测：`yield` 取 1e-6 / 0.0552 / 1.0 / 1e3，
Z5 **全为真**。没有任何物理配置能让它变红。

**代码没写错，错在预注册自己。** Monod 的配置里根本没有氧的位置，
「重扫」这个动作对它不可能有效。这不是可修的实现 bug——**是一条不可能证伪的判据
被写进了冻结文件**，而 §1 的 H1 里就含着这一条合取项。

### 结论不依赖它

Z3 说 dFBA 的产率随氧变（0.055244 → 0.086318，**极差 56.2%**），
Z4 说 Monod 的产率恒定。**常数不可能等于变量超过一点，这是算术。**
Z5 就算做对也是冗余的——它想排除的「Monod 只是没校准」，已被 Z3 ∧ Z4 蕴含。

**所以 H1 保留，产物不覆盖。** 本次以 `PYTHONHASHSEED=0` 重跑，
`real 300.66s`，与已提交产物**逐字节相同**。判定那次是有效的，
不能因为事后发现一个冗余单元空洞就把它抹掉——这与第七世界的处置同一条理由。

### 探测顺带挖出一件产物里没人说过的事

| 声明 `yield` | 表观产率 | 偏差 |
|---|---|---|
| 0.055244 | 0.063683 | **+15.3%** |
| 0.083404 | 0.091582 | +9.8% |
| 0.086318 | 0.094468 | +9.4% |
| 1.000000 | 0.999929 | −0.0% |

**Z4 的判据（相对误差 < 1e-3）只在 `yield=1.0` 附近成立**，而 runner 恰好只用了 1.0。
`pinned_to` 与 `monod_yield_pinned` 这两个数一直躺在已提交的产物里、相差 15%，
**没有任何判据去读它们**。

> **产物记录了反驳自己的证据，而判据没去看。** 这是新的一类坑。

### 处置

1. **不改 runner、不覆盖产物、不编辑冻结的预注册。**
2. 新门 `scripts/gates/vacuous_criterion_scan.py`：对**具名模块级常量**做推导式
   而循环变量未被使用 → 报。`range(n)` 不报（那是正当的重复试验）。
   全树 127 个文件扫下来**零误报**，只命中这两处。
3. 两处记进 `KNOWN_VACUOUS`，**登记精确条数**：多一处或少一处都红（两个方向都实测过）。
   登记项只在它那个文件真被扫到时才核对——「没扫到」不等于「已修好」。
4. `gate_selftest` 加 F22（照 F14 的形状把识别面缩空，要求自检变红）。
