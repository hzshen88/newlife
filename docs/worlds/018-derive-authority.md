## 1. 为什么问这个

十五、十六、十七接了三个第三方 `Process`，三次成色都被降级，理由是同一句：
第三方交付了类型词表、模型与参数、连接线，**但没有一个说过「哪条路径归我、
我只发这类 Effect」**。那一半三次都由我们手写。

> **必须人写，接第三方就无法规模化**——每接一个都要一个懂 newlife 契约的人
> 坐下来写一份声明，而写错了没有任何东西会发现。

**算符正是那一类，而它三个全推对了。**

### 两处 `claims` 差异，经机械分类都不是「信息缺失」

分类是**代码算的，不是散文判断**（`_classify_claims`）：

| provider | 分类 | 差在哪 |
|---|---|---|
| `Grow` | **`layout`** | 手写 `('cell','mass')` vs 推导 `('mass',)`——差的是**我们**在第十五个里程碑自己选的状态布局；去掉各自共同前缀后相同 |
| `MonodKinetics` | **`identical`** | —— |
| `DynamicFBA` | **`finer`** | 推导给出**三条底物各自的路径**，手写只有父路径 `('fields',)`——**手写当初被端口粒度限制**（第十七个里程碑已记的那处损失） |

```

```

> **零项推不出来。瓶颈是可以拆掉的。**
> 差异全部来自手写声明当初的选择或缺陷，不是第三方没交付信息。

## 3. 算符是怎么推出来的：行为探针

不问类型**名**，直接问那个 store 类型**语义**：

```
apply(schema, state=1.0, update=0.5, path=[])
  PositiveFloat → (1.5, [])   求和 → 写入是增量 → add
  SetFloat      → (0.5, [])   覆写 → 写入是绝对值 → set
```

**这不是「只有类型」。** 文献说得对：细粒度权限从接口**类型**推不出来。
但注册类型是一个**可执行对象**——问它「1.0 收到 0.5 会变成什么」问的是语义。
**Y2 每次跑前验一遍探针真能分辨**，否则整套推导没有判定力
（本项目栽过两次「用一个检测不出任何东西的变异去判定通过」）。

## 4. 接线真从第三方拿：一个遍历器吃掉三种形状

三个第三方接线生成器的返回形状各不相同：

| 生成器 | 形状 |
|---|---|
| `get_single_dfba_process` | 顶层就是 process 节点 |
| `get_kinetic_particle_composition` | 节点埋在 `particles/_value/` 下，`inputs`/`outputs` 还裹一层 `{_type, _default}` 壳 |
| `grow_divide_agent` | 返回一个 composite，`Grow` 节点在它里面 |

**没有给每个生成器各写一个提取器**——写了一个递归遍历器，按「地址以类名结尾的
process/step 节点」找。第四个第三方来的时候不用加代码。

`Y1` 用 **AST** 检查推导模块没有 import 或引用任何 `declaration` 常量——
否则「推导」只是把代写权限换成代写接线。

## 5. 一处自打的脸：检查在自己的说明文字上误报

`Y1` 第一版按**子串**查禁用词，结果命中的是 `derive.py` 文档字符串里那段
**「本模块不 import declaration」的散文**，于是判 INVALID。

> 与本项目栽过的「检查太弱」是同一个病的**反面**：**检查太笨。**
> 断言的对象必须是**结构**（AST），不是文本。

## 7. 这个 H0 之后该做什么

差异既然不是信息缺失，两条都是可执行的修正：

1. **`Grow` 的 `layout`**：第十五个里程碑的世界应改用第三方自己给的状态布局，
   手写声明里那个 `cell/` 前缀是我们凭空加的。
2. **`DynamicFBA` 的 `finer`**：要用上推导给出的细粒度声明，`admit()` 需要
   **按 key 逐条发 `StateDelta`**（今天一个端口只发一条）。这正是第十七个里程碑
   记下的「端口粒度限制声明粒度」的修法。

**两条做完，Y3 才有可能三个全过——而那时权限声明就不再需要人写。**
