**文献的公认答案是容器化**——完整流水线要被捕获成含操作系统的容器镜像，因为
「除非依赖被版本化且运行在一致环境中，否则不保证确定性输出」。对手方据此押 H0。
**这次 H1 成立，是因为依赖面薄得反常：声明的依赖只有一个。**

## 2. 但测出了一个未声明的依赖，而它恰好被满足了

> **换一台没有编译器的机器，归档复现会失败。**

goal §5 事前点名了这条：「若它因此失败，那本身就是产出」。它没失败，但**缺口一样存在，
只是被环境掩盖了**。

## 3. 口径必须连着结论一起报

**「纯净」只到 Python 包这一层**：同机、同 OS、同解释器。

**H1 只说明声明的包依赖是完整的。它不说明跨机器、跨年可复现**——而那正是文献里
复现衰减的主因（第十一个里程碑引的 3.4% 就是那一类），**本次完全未覆盖**。
