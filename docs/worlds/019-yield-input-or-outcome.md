## 1. 这是产品形态的第一次端到端

两件事一起测：**科学**（网络层买到什么）+ **产品**（一个只用现成积木的新问题值多少行）。

**问题是积木自己长出来的**：`MonodKinetics` 与 `DynamicFBA` 的输入签名**逐字相同**，
在同一端口可互换；而 dFBA 内部用的**正是 Monod 摄取律**
（源码注释：「Set uptake bounds using Michaelis-Menten kinetics」）。

> **两个积木共用同一条摄取律，差别只在「摄取之后」。**

## 2. 结果

摄取律的对齐**不是手填**——Monod 的 `km`/`vmax` 在运行时从 dFBA 自己的
`kinetic_params` 读出（Z2 机械核对）。扫描 `EX_o2_e`：

| O₂ 下界 | dFBA 产率 | 乙酸 | Monod 产率 |
|---|---|---|---|
| −1 | 0.0552 | **1.216** | 0.99993 |
| −2 | 0.0834 | 0.175 | 0.99993 |
| −4 / −8 / −20 | 0.0863 | 0.000 | 0.99993 |

氧受限 → 分泌乙酸、产率降；氧充足 → 乙酸归零、产率到平台。**教科书式的溢流代谢**，
由第三方积木经我们的契约跑出来。

> **唯象模型把产率当输入（恒等于声明的 `yield`），机制模型把产率当结果。**

**判据的重心是负控 Z5**：把 Monod 的 `yield` 钉到 dFBA 某一点的产率，
它在其余点**仍然不动**——**对齐一个点 ≠ 表示这个自由度**。

## 3. 结论的边界（预注册 §5 事前声明，如实兑现）

**只证「固定形式的 Monod（单反应、常数产率）覆盖不了这个依赖」，
不证「任何唯象模型都覆盖不了」。** 给 Monod 加一条 `glucose→acetate` 反应就能
表示乙酸，但那是**换一个模型**，不是同一个模型的参数化。本轮明确不加。

## 4. 途中撞出一处真实的非确定性

**`PYTHONHASHSEED` 变了，Monod 的表观产率末位就变**（…365 ↔ …363）——
第三方代码路径上有 `set` 迭代，浮点求和顺序随之变。

与第十七个是同一形状（「逐字节复现买到的是同一个求解器的同一个选择」）。
照同样办法处置：**钉住种子并记进产物**，种子不对就重启自己并打印出来。

**补 `flush` 之前那行提示被 `execve` 吞掉了**——重启发生了但没人看得见，
**那就成静默了**。判据本身对这个抖动不敏感（容差 1e-3），但产物要逐字节稳定
就必须钉住它。实测：种子 0 / 3 / 7 下产物逐字节相同。
