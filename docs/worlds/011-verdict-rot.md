## 2. 这个数放在文献里看

计算复现衰减的基准率很难看：27,271 个生物医学 Jupyter notebook，依赖装得上的
10,388 个里只有 879 个产出相同结果——**约 3.4%**；IR 那项研究发现四年后多数产物
在现代环境已无法运行。

**但两者的机制不同，不能直接比**：文献里的衰减是**依赖漂移、跨年发生**；
本项目是**同一台机器、同一环境、几天之内**。**唯一那次失效也不是环境造成的，
是我们自己的第八个里程碑删掉了第七世界判据引用的部件。**

所以这个 7/7 说明的是：**在环境不变的前提下，冻结判据 + 确定性种子确实撑得住。
它没有说明本项目能扛住跨年的依赖漂移**——那从未被测过。

## 3. 起草期做对的一个区分

goal 里我把两个问题混成了一个，design 阶段分开：

| | 能不能保障 |
|---|---|
| **归档复现**：当时那次运行能不能重放 | **能**——`git checkout <冻结 commit>` + 冻结种子 |
| **当下有效性**：今天的代码是否仍满足当时的判据 | **不能，也不该**——系统变了，结论本就该重判 |

**本里程碑测的是第二个。**

## 4. 四态，不是二态

`seventh` 那个不是「值变了」，是**判据在今天的代码上根本解析不了**。两者性质不同：

| 态 | 含义 | 是不是故障 |
|---|---|---|
| `reproduced` | 逐字节复现 | 否 |
| `value_changed` | 跑得通、答案变了 | **不是**——系统演化，结论过期是正常科学结果 |
| `unevaluable` | **问题没了**，判据引用的对象已被删除 | **是** |
| `unrunnable` | 跑不起来 | 不计入 H0 |

**把「答案变了」记成「坏了」会把正常的科学演化误判成故障**，所以预注册把两者混淆列为 IC-2。

## 5. 顺带测到的归档缺口（与 H0/H1 分开）

八份产物里 **6/8 记了自己的冻结 commit**；`second` 与 `fifth` 没记，要靠翻文档才能
定位冻结点——**归档复现（§3 左栏）对这两个不是一条命令**。种子只有 `third`/`fourth` 记，
但 `sixth`–`ninth` 是确定性审计、本无种子，不算缺口。

## 6. 负控

四态里的三个都实测翻转过：

- 把 `ninth` 的冻结产物改一个字节 → **`value_changed`**，verdict 转 H0
- 给 `sixth` 的 runner 加一行 `raise` → **`unrunnable`**，verdict 转 INVALID（**不计入 H0**）
- `unevaluable` 由 `seventh` 实时演示

恢复后两者均回到 `reproduced`，verdict 回 H1。
