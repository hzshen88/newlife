## 2. 科学结论（v3，冻结于 `87dd522`）

复现 Rosenfeld, Elowitz & Alon (2002)：负自调控在**解析匹配稳态**后仍然更快。
`tellurium 2.2.13.1` / `libroadrunner 2.10.0`，经 newlife 契约运行。

**本轮唯一带信息量的是两格盲的**（`a` 只跑过 1.0，其余从没跑过）：

| `a` | 差 `t½(简单)−t½(NAR)` | 比值 `t½(简单)/t½(NAR)` |
|---|---|---|
| 0.5 | 1.09246 | 4.7173 |
| 1.0 | 0.54610 | 4.7102 |
| 2.0 | 0.26963 | 4.4972 |

- **S6 成立**：差随 `a` 严格递减。且 `差 × a` = 0.546 / 0.546 / 0.539——
  **确认了预测的 1/a 标度，不只是方向。**
- **S7 成立**：比值相对极差 **0.0489**（阈 0.10）。

**边界，必须与结论分开写**：S7 的偏离集中在 `a = 2.0`（4.71 → 4.50），
那里 `t½(NAR) = 0.077` 只有约 1.5 个时间步。**这 4.9% 里很可能有一部分是数值分辨率，
不是物理**——判据过了，但**不构成「比值精确不变」的证据**。

## 3. 它在 newlife 里改了什么

**`build_composite` 把节点 `interval` 写死成 1.0**（`foreign.py`），
按 `dt=0.02` 推进时 pb 把请求攒着、累够 1.0 才真跑一次。实测 **251 个采样点只有
5 个不同取值**，变化发生在第 49/99/149/199 步——**而数字看起来完全合理**
（终值 0.9817，解析 0.9933）。这是科学意义上的静默退化：**没有错到能被一眼看出来。**

**十五 / 十六 / 十七 / 十九个里程碑全都没发现**，因为它们无一例外用
`run_composite(composite, 1.0, profile)`，`bare_control.py` 三处也写死 1.0——
**步长与时长恰好相等，不匹配从未暴露。换一个步长的第一个用户当场撞上。**

已修（`7fe921e`）：`build_composite(..., interval=…)`，且 `run_composite` 在时长不是
步长正整数倍时**硬失败**。默认仍是 1.0，既有判定逐字节不变。

> **四个接第三方的里程碑，用的是同一个步长。**「换一个参数」这件事，
> 只有真用户会做。

## 4. 三条方法学教训

**① 试探必须覆盖判据里出现的每一个量，不是覆盖大部分。**
v1 根本没跑试探（窗口太短）。v2 跑了，但**只看了简单调控那一条轨迹的取值数
（401/401），就写了一条关于「每条轨迹」的判据**——NAR 收敛后增量在 float64 里归零，
n=2 得 298/401、n=4 得 177/401。**两次都是「写了关于自己没量过的量的判据」。**

**② 卫生检查属于作废条件，不属于科学合取式。**
v2 的 `S3_timestep_took_effect` 是卫生检查，却同时进了合取式和 IC。
于是**一条会在合法数据上失败的机械检查，否决了一次科学上成功的运行**
（S4/S5/S7 当时全部成立）。而且它已经多余——库层的硬失败刚刚替代了它。
**为一个自己刚在库里修好的 bug 再写一条问题级判据，是自设否决权。**

**③ 确证性的轮次要留一格真盲的，否则它不带信息量。**
v3 的八格里六格的数起草前都已看过，预注册逐条标注了。**唯一没看过的是 `a` 这一维**，
而 S6/S7 正是靠它才有内容。这条对「复现已知结果」这类问题尤其要紧。

## 5. 还没做的

- **`env.lock` 只记 `name==version`**，第三方依赖无内容哈希；newlife 自己那格已用
  源码摘要钉死（`newlife_source_sha256`）。
- **第①阶段（提出问题）在用户那边仍无机械检查**：`check_goal_ready` 认的是
  exloop 的 goal 锚点格式，对 `prereg.md` 用不上。
- **判定层仍只有生成、没有抽象**。现在有了四个真实问题的样本——
  **可以第一次真正测量「多少能抽」了**，而不是靠猜。
