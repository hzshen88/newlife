# 判定层有多少能抽 —— 第一次真测

**2026-09-05。这不是一个里程碑**：没有预注册，`results/` 里没有产物。
本文记录一次**度量**：四个真实 runner 之间重复了什么，重复的是生命周期还是科学。

工具：[`scripts/measure_runner_overlap.py`](../../scripts/measure_runner_overlap.py)。
复跑：

```
python scripts/measure_runner_overlap.py ~/Projects/my-research/questions
```

## 0. 前两次为什么翻车，这次改了什么

| 次序 | 方法 | 结局 |
|---|---|---|
| 一 | 人手三分 | 报了「158 行判定与问题无关」——**从没测过** |
| 二 | 正则量 | 漏了两处，55% **当场作废** |
| 三（本次） | AST + 五条负控 | 负控不全过就退出 1，**不给数字** |

**度量前必须先承认三个陷阱**，否则这次也会翻：

1. **语言差**。模板已译成英文（`7d1aa05`/`f60237f`/`0f8af35`），四个 runner 仍是中文，
   且 i18n 提交在四个问题**之后**。按文本比会被语言差淹没。→ 走 AST：注释天然不进 AST，
   docstring 显式剥掉，`ast.unparse` 规范化空白与引号。
2. **样本不独立**。四个问题里三个是**同一个问题的迭代**（nar v1→v2→v3）。
   它们共享的不只是生命周期，**还有科学**。当四个独立样本算，会把科学误算成「可抽」。
   → 标题数字取**两两交集的下界**，不需要人先声明谁和谁独立。
3. **化妆品**。只差一个变量名或一个打印列宽的两条语句，逐字比是不等的。
   → 近似重复单列，**不进标题数字**。

## 2. 结果

### 2.1 两两交集矩阵（AST 单元）

|  | smoke | nar_v1 | nar_v2 | nar_v3 |
|---|---|---|---|---|
| **smoke** | — | 31 | 30 | 30 |
| **nar_v1** | 31 | — | 74 | 73 |
| **nar_v2** | 30 | 74 | — | 93 |
| **nar_v3** | 30 | 73 | 93 | — |

**双峰，中间是空的**：跨问题 30 / 30 / 31，同问题 73 / 74 / 93。
**没有任何一对落在 32–72。** 判别器成立——这把尺子分得出生命周期和科学。

### 2.2 规模

| 文件 | 原始行 | 代码行 | AST 单元 |
|---|---|---|---|
| `toolchain-smoke` | 118 | 66 | 46 |
| `nar_v1` | 218 | 164 | 96 |
| `nar_v2` | 248 | 188 | 116 |
| `nar_v3` | 258 | 192 | 124 |
| `verdict.py.template` | 134 | 67 | 46 |

**「原始行 / 代码行 / AST 单元」是三个不同的数，不许混着报。**
模板 134 原始行里 **24 行是注释**——立场里那句「约 40 行生命周期」，
按代码行算是 **67**，按 AST 单元算是 **46**。

### 2.3 可抽的部分：**30 个 AST 单元 ≈ 34 个规范化代码行**

占一个真问题（`nar_v3`，124 单元）的 **24%**；占冒烟测试（46 单元）的 **65%**。
**单报一个百分比是误导的**——分母差 2.7 倍。

**模板外为 0。** 30 个共享单元**全部**落在 `verdict.py.template` 里。
两个独立问题，没有任何一处是用户自己手推出来的生命周期。

按位置：`main()` 内 16，模块级 14。按功能：

| 类别 | 单元数 | 内容 |
|---|---|---|
| 样板 / import / CLI | 17 | 9 个 import、`HERE`、`main` 签名、argparse ×3、`mkdir`、`__main__`、`exit_code` |
| 自我复现（S0） | 8 | `INNER`、probe 路径、`subprocess.run`、字节比对、`unlink`、`final`、内层早退、`reproduction.json` 写出 |
| 机械合取 | 2 | `passed = all(...)`、`verdict = decide(...)` |
| 判据自证能红 | 2 | `criteria_can_fail` 签名 + 调用点（**函数体是科学，不共享**） |
| 产物落盘 | 1 | `emit(..., RenderSpec(...))` |

### 2.4 用户预期里的两条，机器说**不**共享

「出身记录」与「环境校验」都**不在**这 30 个里——人手数一定会算进去。真实情况：

| 语句 | 相似度 | 差在哪 |
|---|---|---|
| `u1 = prov['env_lock_sha256'] == provenance.file_digest(...)` | 0.986 | **只差变量名** `s1` → `u1` |
| `for name, unit in units.items(): print(f'{name:38s} ...')` | 0.987 | **只差打印列宽** `34s` → `38s` |
| `print(f"{'S0_byte_identical_on_rerun':38s} {s0}")` | 0.980 | **只差打印列宽** |
| `prov = provenance.snapshot(...)` | < 0.80 | 多两个 kwarg（`tellurium`、`libroadrunner`） |

另有两条相似度 0.97/0.98 的是**真科学**，只是文本碰巧像：
`strictly_increasing` vs `strictly_decreasing`。

**这四条是本次度量最有信息量的部分。** 把它们算进来，生命周期是 **34 个单元**；
更重要的是它们的**性质**：

> 两个独立问题、一个问题的三次迭代，用户对生命周期的改动**全部是化妆品**——
> 两个打印列宽、一个变量名、一个 kwarg 列表。
> **没有一次是为了科学上的需要而改生命周期的。**

## 3. 这对「生成，不抽象」意味着什么

现有立场：模板把生命周期**生成**给用户，代码归他；理由是「少于三个 provider 不许定型」。

**度量支持维持这个立场，但理由变了。**

- 原理由（形状还没定）**已被证伪**：形状没变过。34 个单元一字未动地穿过了
  两个独立问题和三次迭代。
- 新理由（抽象买不到东西）：**用户从不编辑生命周期，所以抽象既省不了他的力，
  也不会破坏什么。** 净收益接近零，而净损失是具体的——
  `newlife check` 的三条门打在**用户自己的文件**上；`unit_alignment` 第一次真实使用
  就抓到「预注册写 S0∧S1∧S2∧S3、代码只算三个」，靠的正是合取写在明处。
  把 S0/S1 藏进 `newlife.run_verdict(...)`，合取就不可见了，门得重新指向库内部。

**但 n 仍然是 2，不是 4。** 三个 nar 版本是同一个问题。项目自己定的「三个 provider」
门槛**没有过**。本次度量能许可的只是**维持**立场，不能许可**改变**它——
两个一致的样本正是冻错接口的经典路径。

## 4. 生成打开了一个洞，度量顺带照出来了

`newlife check` 的三条门是 `unit_alignment` / `vacuous_criterion_scan` /
`silent_degradation_scan`。三条都**不验证生命周期本身还对不对**。

`unit_alignment` 确实按名字认 `S0`（同读 `summary.json` 与 `reproduction.json`），
但它查的是**名字对齐**，不是 S0 **算得对**。一个把 `s0 = True` 写死、
或者把 `probe.unlink()` 挪到比对之前的 runner，**三条门全绿**。

生成模式下，安全绳住在用户可编辑的代码里，而**没有任何东西检查它还是不是原样**。

**本次度量顺带给出了这个检查的形状**：runner 里的生命周期单元必须匹配模板，
差异只许落在一张显式的化妆品白名单里（列宽、变量名、`provenance.snapshot` 的 kwarg）。
**但这条门有真实的误红风险**——上面那四条化妆品差异，天真实现会全部报红，
而它们都是合法的。**先证明它会红、且不会在合法数据上红，再说它有用。**
这一条**没做**，只记录在此。

  不是机器判定；机器给的逐字数字是 **30**。
